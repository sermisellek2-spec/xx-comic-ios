# 阶段完成报告填写规范

创建实际报告时标题写明阶段号、日期和阶段名称。以下是必填字段，不是预先完成的验收结论。

1. **状态**：待 Codex 验收 / 自检存在阻塞。不要写“全部验收通过”。
2. **代码基线**：分支、开始 commit、结束代码 commit、未提交修改及归属；报告文档的提交另列，避免自引用哈希。
3. **范围对照**：将该阶段要求逐项列为完成/未完成，给文件路径与行为证据。
4. **页面变化**：新增页面/抽屉/状态、浅深色截图路径、动画录屏路径、窄屏和大字体检查。
5. **数据影响**：数据库版本/迁移、文件目录、身份与进度、清理规则；旧收藏/历史是否保留。
6. **验证证据**：准确命令、退出码、测试数量、关键断言、设备型号/API、联网条件；未执行项目及原因。
7. **验收 APK**：绝对路径、版本名/码、applicationId、签名 SHA-256、文件 SHA-256、覆盖安装前提。
8. **人工操作步骤**：准备材料 → 点击路径 → 预期结果；含取消、失败、重启、断网和恢复。
9. **已知限制/风险**：具体触发条件与影响，不能用“无”掩盖未测项目。
10. **回退方式**：只回退本阶段的明确提交；本地数据和数据库向前兼容限制、保全数据方法；不得指示 reset --hard 或删用户数据。
11. **验收记录**：Gemini 自检结论；Codex 结论“待填写”；用户真机结论“待填写”。只有对应验收人可更新后两项。
12. **停止声明**：当前阶段已停，未开始下一阶段，未合并 master、未发布 COS。

提交前检查敏感 URL、Cookie、验证码凭证、原文件内容未进入日志或截图。使用自制/授权的测试漫画和图书样本。
