# 搜索列表下拉刷新设计

## 目标

消除从其他 Tab 返回搜索页时封面重复闪动，并为搜索结果列表增加保留当前条件的下拉刷新。

## 范围

- 仅修改 `MainActivity.java` 和对应 `tools/check-*.js` 契约测试。
- 使用现有平台 `ScrollView`、`ProgressBar`、触摸事件和动画 API。
- 不引入 AndroidX 或其他依赖，不把搜索页迁移为 `ListView`。

## 切回搜索页

已有 `searchResults` 时，从其他 Tab 返回搜索页只重建并显示现有结果，不再设置或消费 `defaultSearchRefreshPending`，也不自动重新请求默认分类。

首次进入搜索页且结果为空时，继续按现有逻辑加载默认站源第一页。用户主动搜索、切换筛选或点击重新加载时，继续正常发起请求。

## 下拉刷新

仅当搜索结果 `ScrollView` 位于顶部、没有搜索加载、分页追加或现有下拉刷新时，才识别向下拖动。

拖动期间使用原生顶部 `ProgressBar` 和列表位移提供反馈。下拉达到约 `72dp` 后松手触发刷新；未达到阈值或收到取消事件时恢复原位，不发请求。

刷新保留当前：

- 搜索关键词；
- 选中站源；
- 地区筛选；
- 连载状态筛选。

关键词为空时重新请求当前分类第一页；关键词非空时重新请求当前搜索第一页。刷新成功后替换结果、将分页重置到第一页，并继续允许加载下一页。

## 异步与错误

下拉刷新复用现有 `searchGeneration`、站源 ID 和筛选参数快照。刷新期间禁止重复下拉和分页请求。切 Tab、新搜索或切换筛选会使旧刷新回调失效。

刷新开始时保留旧结果，不显示整页 loading 骨架。成功后更新结果；失败时保留旧结果、结束刷新指示并使用现有轻提示记录错误，不进入整页错误页面。

## 验收

1. 有结果时在其他 Tab 与搜索 Tab 间切换，封面不因自动默认刷新再次闪动。
2. 列表顶部下拉不足阈值不请求，超过阈值松手只请求一次。
3. 下拉刷新请求第一页，并保留关键词、站源、地区和状态。
4. 刷新期间不能同时分页或再次刷新。
5. 刷新失败保留旧列表并恢复可操作状态。
6. 刷新过程中切 Tab，旧结果不能覆盖之后的页面。
