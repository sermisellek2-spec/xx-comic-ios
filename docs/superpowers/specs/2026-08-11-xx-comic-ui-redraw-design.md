# XX Comic 视觉重绘与 Material 3 优化设计

## 背景

XX Comic 当前是原生 Android Java 应用，界面由 `MainActivity` 和 `UIHelpers` 直接构建。此次工作先以当前 App 为唯一参照，制作完整可点击的 1:1 浏览器原型；用户审核基线后，再在不改变功能、文案和导航层级的前提下制作 Material Design 3 优化版。两版审核完成前，不修改 Android 业务代码。

## 目标

1. 完整还原当前 App 的视觉界面和主要交互状态。
2. 使用固定模拟数据提供可点击、可切换状态的浏览器原型。
3. 保留 1:1 基线，制作可直接对照的 Material 3 品牌化优化版。
4. 优化版只调整视觉系统、排版、间距、组件样式和信息层级。
5. 以手机竖屏 `393 × 873dp` 为基准，并保证 `360–430dp` 宽度不破版。

## 非目标

- 不接入真实站源、网络请求、缓存、导入导出或本地持久化。
- 不新增、删除或重命名 App 功能和用户文案。
- 不调整底部导航目的地和页面层级。
- 不在原型阶段迁移 Compose、重构 `MainActivity` 或修改 Android 业务逻辑。
- 不完整采用 M3 Expressive 的装饰性形状、动态排版和形变动效。

## 交付与审核顺序

1. 制作完整 1:1 原型，用户逐页审核。
2. 保留已审核基线，制作 Material 3 优化版。
3. 用户审核两版差异并确认最终视觉方向。
4. 视觉方案确认后，另行制定 Android 落地计划。

原型使用仓库根目录下一个无需构建工具的 `index.html`。通过 `?design=baseline` 和 `?design=m3` 提供两个不可覆盖的视觉模式，两版共用模拟数据、页面状态和交互语义。审阅控件位于手机画布外，不进入正式 App 界面。

## 页面覆盖

### 主页面

- 收藏：标题、搜索入口、收藏列表、侧滑删除和空状态。
- 搜索：搜索框、站源与筛选入口、双列结果、下拉刷新、分页和重试。
- 站源：启用与停用站源卡片、站源操作菜单。
- 我的：阅读历史、主题、左右手模式、缓存、错误日志和关于。

### 二级页面

- 全局搜索与搜索历史。
- 全站搜索结果和站源结果切换。
- 漫画详情。
- 阅读器。
- 阅读历史。

### 浮层与状态

- 搜索筛选抽屉。
- 章节目录抽屉。
- 站源菜单。
- 信息、确认、错误和日志弹窗。
- Toast 提示。
- 日间、夜间、正常、空、骨架加载、分页加载、错误和重试状态。

## 原型架构

原型不引入框架或依赖。一个普通 JavaScript 状态对象保存以下内容：

- 当前视觉模式、主题和审阅状态。
- 当前页面、底部 Tab 和返回目标。
- 当前漫画、章节、搜索词、筛选项和选中站源。
- 收藏、阅读进度、抽屉、弹窗和 Toast 状态。

用户操作只执行“更新内存状态，然后重新渲染”。两种视觉模式调用相同的路由和交互函数，仅通过设计令牌、组件类和必要的布局分支产生视觉差异。原型关闭或刷新后恢复默认模拟状态，不写入 `localStorage`。

## Material 3 优化方向

采用“Material 3 组件体系 + XX Comic 品牌皮肤”，不使用默认 Material 配色直接覆盖产品。M3 只进入优化模式，1:1 基线保持不变。

### 设计原则

- 漫画封面仍是第一视觉，组件退居内容之后。
- 使用 M3 颜色角色和表面层级，不以阴影表达所有层级。
- 保留 XX Comic 的琥珀品牌信号，同时加入冷中性色和绿色语义色，避免单一暖色主题。
- 表达性形状只用于选中态和关键操作，不进入阅读内容区。
- 使用类型角色建立层级，仅在详情标题等重点位置使用强调字重。
- 不启用壁纸动态取色，保证品牌和漫画封面之间的颜色稳定性。

### 组件映射

- 搜索：使用 Contained Search。保持持久填充容器、低 elevation 和前后图标能力。
- 底部导航：使用 Flexible Navigation Bar。保留 4 个固定目的地、取消阴影，并使用 pill 指示选中项。
- 搜索结果：使用 Filled Card，但尺寸与当前基线一致；不放大卡片或封面。
- 章节入口：使用 Outlined Card，避免所有内容都浮起。
- 筛选：使用 Filter Chips。选中项使用 Primary Container，未选中项使用 Outline Variant。
- 阅读主操作：使用 Filled Button；收藏等次要操作使用 Tonal Button。
- 筛选和章节目录：使用 Modal Bottom Sheet，顶部圆角 `28dp`，包含可访问的拖动把手。
- 删除确认和重要提示：使用单任务 Basic Dialog；错误日志等长内容允许 Full-screen Dialog。
- 站源开关：使用 M3 Switch，并保留明确的文字状态。

默认按钮使用 `40–48dp` 视觉容器和完整圆角；当容器低于 `48dp` 时，外层触控区域仍须达到 `48dp`。图标与标签共享同一内容颜色，按钮文案保持简短。

## 状态与交互

### 页面流

- 收藏页搜索入口进入全局搜索。
- 搜索结果、全站结果、收藏和历史均可进入详情。
- 详情可收藏、开始或继续阅读，并打开章节抽屉。
- 阅读器可切换工具栏、上下章、目录和全屏。
- 返回操作按照当前 App 的层级恢复来源页面。

### 审阅状态

手机画布外提供审阅面板，可切换：

- 1:1 / M3 视觉模式。
- 日间 / 夜间主题。
- 正常 / 空 / loading / error 状态。
- `360 / 393 / 430dp` 预设宽度。

审阅面板只服务视觉验收，不出现在 App 模拟界面中。

### 错误处理

- 缺少模拟数据时显示对应空状态，不渲染残缺卡片。
- 详情、目录和阅读加载失败时提供明确错误文案和重试动作。
- 分页失败保留已有结果，只替换底部状态为重试入口。
- 无启用站源时保留当前 App 的引导路径。
- 所有关闭、返回和重试操作必须回到可预测的页面状态。

## 无障碍

- 正文与背景对比度至少 `4.5:1`。
- 启用控件与背景的可辨识对比度至少 `3:1`。
- 触控区域至少 `44dp`；M3 主控件优先采用 `48dp`。
- 图标按钮提供与可见动作一致的标签。
- 状态不能只依赖颜色表达，须同时提供图标或文字。
- 文字放大到 200% 时，按钮标签最多两行且不截断；关键内容不得重叠。
- 抽屉和弹窗打开后保持清晰的焦点顺序，并可通过返回操作关闭。

## 验收与测试

### 自动检查

- HTML 和内联 JavaScript 可解析。
- `baseline` 与 `m3` 两种设计模式可独立打开。
- 页面地图中的所有页面和浮层均有稳定入口。
- 主要按钮、Tab、抽屉、弹窗、主题和审阅状态可切换。
- 不包含真实网络请求和外部运行时依赖。

### 视觉检查

- 在 `360 × 800`、`393 × 873` 和 `430 × 932` 视口检查日间与夜间主题。
- 检查文字、控件、浮层、导航和 Toast 不重叠、不溢出。
- 检查搜索卡片保持基线尺寸和双列密度。
- 检查 loading、空和错误状态不会改变固定布局的尺寸。
- 用户先审核 1:1 模式，再审核 M3 模式和两版差异。

## 实施边界

实现阶段优先复用现有 `tools/check-prototype.js` 的契约检查思路，但只保留与本设计相关的最小断言。原型审核完成前不修改 Android UI。后续 Android 落地继续使用现有 Java View 技术栈，并评估 Material Components for Android Views；迁移 Compose 不属于本设计。
