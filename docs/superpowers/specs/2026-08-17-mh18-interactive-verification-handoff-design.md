# 18漫画交互验证接管设计

## 目标

修复 18漫画首次加载漫画列表时，Cloudflare 要求勾选“验证您是真人”却因后台 WebView 不可操作而等待 120 秒超时的问题。验证必须尽量静默；只有确实需要人工操作时展示验证页，用户完成勾选后立即回到 App，网页后续跳转和原列表请求在后台继续。

## 已确认根因

- 18漫画普通 HTTP 请求返回 Cloudflare `403 challenge`，因此列表解析前必须先取得有效浏览器凭证。
- 自动列表请求当前以 `interactiveAllowed=false` 创建，检测到挑战后只保留离屏、透明且不可点击的 WebView。
- Android WebView 上的本次挑战要求 Turnstile 人工勾选，挑战 DOM 因此始终存在，页面状态机只能等待到 120 秒超时。
- 列表解析器尚未取得业务 HTML，这不是漫画卡片或分类解析错误。

## 设计

1. 为 `CloudflareWebViewSession` 增加独立的“自动请求允许必要交互”配置，只在 18漫画会话开启；禁漫天堂继续使用原构造与原行为。
2. 18漫画先保持后台静默验证。挑战持续超过现有 4 秒自动窗口后，将同一个 WebView 移回屏幕并允许用户完成 Turnstile。
3. 页面检查同时读取 Turnstile 隐藏响应是否已经生成，并比较本次挑战前后的 `cf_clearance`。任一信号确认用户交互已经提交后，立即把验证 WebView 移回后台，不等待目标网页视觉加载完成。
4. 后台 WebView 保持存活，等待 Cloudflare 完成跳转、Cookie 落盘和真实目标页加载。只有挑战 DOM 消失且目标页 `readyState=complete` 时才提示“验证完成”并捕获页面。
5. 原列表请求在同一串行会话内继续，成功后按现有顺序加载分类。凭证有效期间，后续列表、分页、搜索、详情、目录和正文复用浏览器上下文。
6. 清除 App 缓存仍会清除 Cookie、WebStorage 和会话就绪状态；超时与失败继续写入现有错误日志。

## 边界

- 不自动点击或绕过 Turnstile。
- 不修改禁漫天堂站源、解析器或会话构造。
- 不新增依赖、后台服务或第二套验证队列。
- 不在用户勾选后销毁 WebView，避免凭证尚未落盘导致再次验证。

## 验收

- 18漫画自动加载遇到可自动通过的挑战时不显示网页。
- 必须勾选时，4 秒后显示可操作验证页；勾选提交后立即隐藏。
- 验证完成后原列表请求自动返回，漫画列表与分类继续加载。
- 18漫画验证配置与禁漫天堂保持隔离。
- 单元测试、源码契约、Release 构建、APK 身份与签名检查通过。
- COS 主安装包和服务器备用包与本地 Release APK 的大小及 SHA-256 一致。
