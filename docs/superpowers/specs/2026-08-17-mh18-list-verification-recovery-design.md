# 18漫画列表验证恢复设计

## 目标

修复 18漫画首次进入后列表和分类长期停留在加载状态的问题，同时保持禁漫天堂的会话构造和运行行为不变。

## 根因

- 18漫画普通 HTTP 请求会快速返回 Cloudflare `403 challenge`，数据页本身可在浏览器验证后正常加载。
- 自动验证 WebView 当前被测量为 `1 x 1`，Cloudflare 在部分 Android WebView 环境中无法完成需要真实视口的挑战。
- 切换站源时列表和分类同时请求同一个串行会话，第二个请求会连带等待第一个请求的 120 秒期限。

## 设计

1. 给 `CloudflareWebViewSession` 增加可选的后台完整视口模式；旧构造函数继续使用 `1 x 1`，所以禁漫天堂行为不变。
2. 只有 18漫画创建会话时开启完整视口。后台容器移出屏幕、保持透明且不可点击，使 WebView 获得真实尺寸但不遮挡或阻塞 App。
3. 将 18漫画加入“首屏列表成功后再加载分类”的现有顺序加载策略，避免首次验证期间争用会话。
4. 保留现有一次验证、浏览器上下文复用、120 秒总超时和手动验证入口，不增加轮询、持久队列或新依赖。

## 验收

- 18漫画后台 WebView 使用完整视口，禁漫天堂仍使用旧的紧凑后台布局。
- 18漫画首屏先请求列表，列表完成后再请求分类。
- 共享会话、18漫画和禁漫天堂现有测试全部通过。
- Release APK 构建、签名、COS 上传和公网回下载哈希核验通过。
