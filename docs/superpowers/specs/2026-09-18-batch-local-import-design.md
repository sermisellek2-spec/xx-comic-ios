# 批量本地导入与多卷合集设计

日期：2026-09-18

## 目标

让用户一次导入数百个 EPUB/MOBI 文件时可以快速返回书架，并在后台增量整理；属于同一部漫画的多个文件在本地显示为一本漫画，但每个文件仍作为独立卷保存和解析。

## 边界

- 不拼接 EPUB/MOBI 二进制文件，不默认重新生成一个大 EPUB。
- 保留现有 ZIP/CBZ、EPUB、PDF、MOBI 导入和阅读入口。
- 站源身份可选；没有站源身份时，用户确认后使用本地合集身份。
- 快速阶段只做结构和元数据扫描；页面图片按需解码，完整检查作为后台/手动操作。
- 下载文件仍使用私有持久目录；可直接访问的外部文件继续遵循现有外部引用约束。

## 数据模型

`LocalSeries` 表示书架上一部本地漫画，`LocalVolume` 表示属于它的一个文件。现有单文件 `Book` 作为兼容视图，迁移时每本旧书生成一个默认卷。

合并身份：

1. 站源下载使用 `(sourceId, comicId)` 作为自动合集键。
2. 本地导入使用用户确认生成的 `seriesId`。
3. 仅按标题生成候选建议，不自动跨来源合并。

卷身份使用 `(seriesId, fileId 或 contentHash)`；同一哈希去重，同一 fileId 的新 revision 原子替换旧卷。

## 快速导入流程

1. 选择文件/文件夹后立即枚举扩展名和最小文件信息。
2. EPUB 读取 container、OPF metadata、spine/nav 和封面入口；MOBI 只读取头部元数据与现有格式检测结果。
3. 通过书内系列名、卷号、文件名规范化和文件夹名生成候选分组。
4. 用户确认分组和顺序后创建导入会话，立刻返回本地书架。
5. 后台队列最多并发 2 个文件；每卷独立 staging、校验、解析和数据库事务。
6. 第一卷完成即可阅读；其余卷完成后增量合并目录和统计。

## 排序

用户调整顺序 > 书内卷号/系列元数据 > 文件名卷号 > 自然文件名 > 选择顺序。卷内章节继续使用 EPUB spine/nav 或 MOBI 适配器顺序。

## 完整性与失败

- 文件下载已有强哈希时复用哈希；本地导入先用大小/修改时间/URI/局部指纹去重，完整 SHA-256 在后台计算。
- 快速导入只验证容器和目录；页面解码失败在阅读时报告，后台可触发完整检查。
- 单卷失败不回滚其他卷；旧版本替换失败时继续保留旧卷。
- 删除单卷只删除该卷，删除合集才删除所有卷和衍生缓存。

## 页面

- 导入抽屉显示快速扫描进度和候选分组确认。
- 本地书架卡片显示合集名称、已完成卷数/总卷数和整理状态。
- 本地详情按卷分组目录，支持添加文件、调整顺序、移除卷。
- 下载中心按合集聚合任务，仍可操作到单卷。

## 验收指标

- 400 个文件扫描不阻塞主线程并能先返回书架。
- 32 卷同名漫画最终只有一个书架项目。
- 任意一卷失败不影响其他卷阅读。
- 重复导入同一文件不新增卷；新 revision 不破坏旧进度，成功后再替换。
- 普通缓存清理不删除导入/下载文件。
