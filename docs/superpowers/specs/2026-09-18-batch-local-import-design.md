# 批量本地导入与多卷合集设计

日期：2026-09-18

## 目标

让用户一次导入数百个 EPUB/MOBI 文件时可以快速返回书架，并在后台增量整理；属于同一部漫画的多个文件在本地显示为一本漫画，但每个文件仍作为独立卷保存和解析。

## 边界

- 不拼接 EPUB/MOBI 二进制文件，不默认重新生成一个大 EPUB。
- 保留现有 ZIP/CBZ、EPUB、PDF、MOBI 导入和阅读入口。
- 站源身份可选；没有站源身份时，用户确认后使用本地合集身份。
- 快速阶段只做结构和元数据扫描；页面图片按需解码，完整检查作为后台/手动操作。
- 下载文件仍使用私有持久目录；可直接访问的外部文件继续遵循现有外部引用约束。

## 数据模型

现有 `Book` 直接表示合集身份，新增 `local_volumes` 表示独立文件，避免重复的 Series 表。章节和页面记录卷归属。旧导入书迁移为默认卷，旧追加文件迁移为各自的卷；保留既有章节、页面与阅读定位 ID。

合并身份：

1. 站源下载使用 `(sourceId, comicId)` 作为自动合集键。
2. 本地导入使用用户确认生成的 `seriesId`。
3. 仅按标题生成候选建议，不自动跨来源合并。

本轮卷身份使用 `(bookId, contentHash)`；同一哈希去重。未来文件站源的 `fileId/revision` 原子替换另行接入，不改当前在线下载路径。

## 快速导入流程

1. 多选文件后在后台枚举扩展名和最小文件信息。图片文件夹沿用原导入功能；文件夹内批量发现电子书不在本轮。
2. 快速扫描只读取 EPUB container、OPF metadata、封面入口，或 MOBI 头部；不解码图片、不复制全文件。无法随机读取的文件提供方退回文件名识别。spine/nav 留到确认后的解析阶段。
3. 通过书内系列名、卷号和文件名规范化生成候选分组；可手动选择“全部合为一本”。
4. 用户确认分组和顺序后创建导入会话，立刻返回本地书架。
5. 后台队列最多并发 2 个文件；每卷独立 staging、校验、解析和数据库事务。
6. 第一卷完成即可阅读；其余卷完成后增量合并目录和统计。
7. 已有漫画详情支持“添加分卷”，必须显式选择目标；不能因同名或首文件重复就绑定另一部已有漫画。
8. 批次逐文件保存日志。切换 App 内页面可以继续；进程终止或 Activity 重建后暂停，下次由用户继续，已完成项不重复处理。当前不新增前台服务。

## 排序

用户调整顺序 > 书内卷号/系列元数据 > 文件名卷号 > 自然文件名 > 选择顺序。卷内章节继续使用 EPUB spine/nav 或 MOBI 适配器顺序。

## 完整性与失败

- 本地文件在后台复制/读取时计算完整 SHA-256 去重，不用局部指纹宣称内容相同。初步扫描无需全量哈希。
- 快速导入验证容器和目录；页面解码失败在阅读时报告。手动全量图片检查留作后续工具。
- 单卷失败不回滚其他卷；取消保留已完成卷，失败项可重试。目标合集被删除后不能被后续导入重建。
- 删除单卷只删除该卷，删除合集才删除所有卷和衍生缓存。

## 页面

- 导入抽屉显示快速扫描进度和候选分组确认。
- 本地书架卡片显示合集名称和已完成卷数，顶部蕾姆横幅显示整个批次进度/继续/取消；本轮不在每张卡片重复展示批次总数。
- 本地详情按卷分组目录，支持添加文件、调整顺序、移除卷。
- 下载中心按合集聚合、文件源 revision 替换属于后续扩展，不纳入本轮本地多选导入验收。

## 验收指标

- 400 个文件扫描不阻塞主线程并能先返回书架。
- 32 卷同名漫画最终只有一个书架项目。
- 任意一卷失败不影响其他卷阅读。
- 重复导入同一文件不新增卷；调序按稳定章节 ID 保持阅读位置。
- 普通缓存清理不删除导入/下载文件。

## 验证边界

自动化覆盖分组、轻量元数据、真实文件日志恢复、按卷读取与目录绑定。SQLite v1 迁移、单卷删除及真机 32/400 文件性能需设备验收；AndroidTest 编译成功不能当作已在设备通过。
