# 受保护站源导航会话设计

## 背景

18漫画和禁漫天堂共用 `CloudflareWebViewSession`。当前会话先打开固定验证地址，验证完成后再通过页面内 `fetch()` 请求真实目标。这个第二次自动请求会再次触发 Cloudflare，导致18漫画翻页反复验证；禁漫分类请求失败后又被发现页静默忽略，因此分类类型和分类都不显示。

实测结果：禁漫验证完成后，在同一浏览器会话中直接导航到第二页不会再次验证；当前 `/theme/` DOM 仍包含七组分类，现有分类解析器可以全部识别。

## 设计

共享会话改为单次导航流程：

1. WebView 在后台直接加载调用方请求的目标 URL。
2. 页面加载完成后只检查标题、可见文本和 URL。
3. 普通页面直接通过 JavaScript bridge 返回 `document.documentElement.outerHTML`。
4. 挑战页首次出现时才展开验证层；轮询期间不重复展开或重新加载。
5. Cloudflare 验证完成并跳回目标页后，直接读取当前 DOM，不再发送第二个 `fetch()`。

同一个 WebView、CookieManager 和 DOM Storage 在 Activity 生命周期内持续复用。漫画图片缓存和页面解析缓存清理不调用 CookieManager、WebView `clearCache()` 或站点存储清理，因此验证凭证继续保留。

## 状态与错误

页面检查只产生四种动作：等待页面完成、首次展示验证、继续等待验证、捕获当前 DOM。请求超时、页面加载错误和 bridge 返回异常继续沿用现有轻提示。分类加载失败仍不伪造分类数据，本次通过修复请求链路恢复真实七组分类。

## 验证

- 单元测试覆盖四种页面动作及挑战识别。
- 源码契约确保会话直接 `loadUrl(request.url)`、捕获 `outerHTML`，并且不再包含 `fetch(url)`。
- 运行完整单元测试、Release 构建、APK 包名/版本/签名/SHA-256 校验。
- COS 与备用地址更新后分别回下载并与本地 APK 比对。
