# iOS 移植执行基准

用户于 2026-09-19 确认由 Codex 开始移植，并指定 Android 开发会话 `019ff5f9-ea38-7923-acae-70fec60ad6bc` 为背景。此前设计草案是原工作区未提交文件；本文作为独立工作区的执行基准。

## 目标

完整移植现有 Android 客户端业务和视觉行为，采用 Swift + UIKit，最低 iOS 16，核心逻辑为独立 ComicCore Swift Package。保留中文、蓝白主题、书架/发现/设置导航和现有视觉素材；不增加账号、后端、数据统计上传或云同步。

基准升级为 Android 2.0.29 / 229，提交 `0d41c22f6917fb471e663fc3dbb40c2c39ed6d9c`。`ios/android-baseline.json` 固定 254 个源码、资源和测试文件的字节 SHA-256。读取旧会话获得背景，不将过期设计覆盖较新的最终决定和实际源码。

## 会话中应保留的规则

- 书架默认入口、继续阅读、收藏和历史均保留；移除收藏不删除历史和位置。
- 发现页单站/全站切换，输入时不发请求，提交时发请求。全站每源只查第一页，同名结果稳定置顶并显示小红点，不按作品名去重；异步结果不抢走用户手动选择。
- 同名只按 Android String.trim 后严格相等判断，不做大小写、全半角、Unicode 规范化或标点删除。
- 详情不预载目录；用户打开目录时请求，抽屉关闭后允许解析结果缓存，不阻塞收藏和续读。
- 左右手只改变手势方向，逻辑页序不倒置。图片索引、图内偏移和章节位置保留。
- 全局主题原有自动模式按时间；阅读主题独立，默认跟随系统，另外可固定深色/浅色，不能给原图加滤镜。
- 去白边和禁止动画翻页默认关闭。裁剪只影响展示，先还原站源图片，再后台保守检测；条漫只裁左右，单页处理四边。不确定就保留原图，切换不重建整个阅读器。
- 一次手势最多翻一页/章，取消、多指、缩放和平移不能误翻；关闭动画不等于关闭滑动识别。
- 本地历史适应目录合并、缩短、删除及旧位置越界，不以删除用户数据规避异常。
- 启动书架习惯完全本地：有效阅读时间和主动操作合计，最近 30 天最多 10 次、至少 5 次、达到 70% 才形成偏好；人工固定优先。
- 旧会话中的后台统计提案已取消，不纳入 iOS 范围。
- 漫画屋是退役站源，不能把旧 README 的“内置站源”列表当作当前可用清单。

## 全量范围与分阶段交付

1. 工程、构建通路、核心模型与规则测试。
2. 在线站源、搜索/筛选/换源、详情、目录、在线阅读、收藏、历史、配置和日志。
3. 需验证站源的 WKWebView 会话、Cookie 同步、图片还原和全部当前站源。
4. 本地漫画、自然排序、批量导入、分卷、EPUB/MOBI/PDF、取消和中断恢复。
5. 下载队列、去重、重试、离线阅读和恢复。
6. 视觉、手势、性能与完整设备回归。

阶段一提供的页面是明确标识的开发预览，不代表在线阅读或 1:1 UI 已完成。每一阶段列出真实通过、失败和未运行的检查。

## 平台差异与验证条件

- APK 自安装更新不能复刻；iOS 安装和续签通过用户选定的侧载渠道进行。
- 后台执行和文件访问遵循 iOS 沙盒/系统调度，持久化任务状态并恢复，不承诺强制退出后继续解析下载。
- Android 系统返回手势不能原样移植；iOS 导航必须始终可退出。最终导航样式以原交互意图和 iOS 可操作性对照验收。
- 字体、系统栏、权限弹窗存在系统差异，内容区仍需截图对照。
- Windows Docker 可执行 Linux Swift 核心测试，不能编译 UIKit 或打包 iOS 应用。
- macOS/Xcode 构建和 iPhone 验收仍必需。GitHub 仓库由用户创建，当前未提供；不自动公开仓库、上传 Android 代码、购买服务或处理用户 Apple 账号。
- 全量完成要求功能矩阵逐项验收且无已知阻断问题，不承诺绝对零 bug。
