# 受保护站源全链路修复设计

## 目标

修复 18漫画与禁漫天堂在搜索、详情、目录和阅读链路中的确定性问题，同时减少无意义的 Cloudflare 验证和重复请求。保持现有 `ComicSource`、`BrowserSession` 和 UI 结构，不引入依赖，不重构无关模块。

## 根因与处理

1. 单站搜索滚动监听会在布局变化或内容未铺满时继续触发加载；分页结果只看“非空”，未判断是否出现新漫画。滚动加载改为只响应用户向下滚动，并按 `comicId` 去重；追加页没有新 ID 时立即结束分页。
2. 18漫画搜索 URL 未使用 `page`。第二页起使用 `/s/{keyword}/page/{page}`，并用 fixture 锁定搜索、详情 JSON-LD、目录与正文图片解析。
3. 全站搜索对所有站源统一 10 秒超时，而受保护站源浏览器验证允许 180 秒。18漫画和禁漫天堂使用 185 秒上限，其他站源仍保持 10 秒。
4. 详情首次拉取完成后又后台拉取详情和目录。首次详情标记为已刷新；缓存详情后台只刷新详情元数据并保留已有目录，目录继续在抽屉打开时异步加载。
5. 禁漫目录扫描整个详情页且会伪造第1话。目录只接受 `.episode` 区域内同时具备 `data-album` 与 `h2_series` 的章节，不再伪造章节。
6. 禁漫解扰使用了错误的 MD5 值、包含扩展名，并在边界上差一位。改为 `MD5(aid + 不含扩展名的文件名)` 的十六进制末字符字符码，按 `aid >= 421926` 使用 `% 8`，否则 `% 10`。
7. WebView 只检查 HTML 非空，可能把错误页或重定向后的其他页面交给解析器。捕获主文档 HTTP 状态，挑战页交给验证，其他 HTTP 错误直接失败；最终页面必须与请求 URL 同站且路径一致。

## 数据流与失败策略

用户触发搜索或打开详情后，站源请求仍通过各自 `ComicSource`。受保护域名由持久 WebView 会话串行导航；只有真实挑战页才展开验证层，验证完成后捕获目标 DOM。解析器只返回与当前请求匹配的数据；分页重复、目录区域不匹配、正文参数缺失均以明确终止或轻量错误结束，不继续循环调用。

## 验证与发布

新增 JVM 回归测试覆盖分页去重、18漫画分页 URL/解析、禁漫目录范围与解扰公式、WebView URL/HTTP 判定。随后运行完整单元测试、源码契约、Release 构建、APK 包名/版本/签名检查。发布 `1.0.30 (30)` 到 COS `apk/xx-comic/xx-comic.bin` 和服务器备用地址，并回下载核对 SHA-256。
