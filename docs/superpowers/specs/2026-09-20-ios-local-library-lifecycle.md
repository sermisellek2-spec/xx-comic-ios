# 本地批量、分卷与恢复执行设计

沿用 Android 2.0.29 / 229 的用户结果和既有 iOS 移植基准。本文补全后续实现边界，不表示功能已完成。站源新增仍暂停。现有图片、文件夹、ZIP、EPUB、PDF、Kindle 的解析/阅读规则保持；实现复用系统 API 和已安装依赖。

## 身份和存储

- 现有 UUID 目录继续是一份物理卷，内部 book.json 和格式资源不移动；`LocalLibrary.book(id:)`、页地址和电子书资源 URL 保持物理卷语义。
- 用户书架上的作品使用独立的系列身份。旧单卷书默认是同 UUID 的隐式单卷系列，首次变为多卷时保留作品 ID、首卷 ID 和已有章节 ID。
- 系列中的卷顺序与章节 ID 分离。拖动仅改变顺序，不重建章 ID；阅读记录仍以作品 ID + 稳定章 ID 查找。物理卷内资源路径不拼接成虚假的单份 EPUB。
- 新增一份版本化原子 JSON 目录快照，记录显式系列、有序物理卷引用、正在删除状态及内容指纹墓碑；由 App 单实例 actor 串行变更。复用现有 Foundation 原子快照约定，不增加 SQLite 或第三方数据库，不改变阅读历史存储文件。
- 旧书仍从原目录读取，不进行全库搬迁。显式目录快照优先；新卷在暂存元数据中带归属标记，发布到物理目录后、系列快照提交前保持隐藏。只有引用它的系列快照提交成功，才在书架出现。
- 快照失败不能让内存显示成功。文件发布成功但快照未提交的孤儿仅在启动、尚无活跃导入/恢复任务时按明确归属恢复或清理，不能运行中扫描删除全部暂存目录。坏快照保留并报错，不能视为空库覆盖。

选择单份 JSON 快照，是为了把系列引用、删除状态与指纹墓碑放在同一原子提交中。相较每书 collection.json 加另一份墓碑表，少一个跨文件事务；相较移动嵌套卷目录，保持现有已验证的资源路径。代价是变更需要重写有界目录快照，未来容量超限必须明确报错，不能静默丢条目。

## 先准备，再发布

现有导入函数将解析和最终发布放在同一调用中。后续最小拆分为内部“准备完整物理卷”和“发布准备结果”，现有公共单卷导入函数仍按原行为组合这两步。

- 每次准备使用独有暂存目录，完成真实解析、必要图片探测、CRC、格式校验及原包/内容指纹计算。未完成的结果不对书架可见。
- 原包指纹必须来自本次稳定拥有副本，不能先 hash 外部文件、再从可能变化的原路径复制。ZIP 也从同一拥有副本解析；文件夹清单使用原相对路径和已经复制的图片字节，不能使用平铺生成文件名冒充 Android 的清单身份。
- 系列协调器在发布前串行处理同指纹去重、目标存在性及墓碑身份。重新导入可恢复旧作品/卷/章身份和用户标题；原目录仍被有效书占用时不能覆盖它。
- 准备阶段的临时身份可以在发布前调整，正式 book.json 与章 ID 必须一次写成最终身份。已经可见的书不能先发布再补改 ID/归属。
- 同指纹普通导入返回已有作品；显式追加到不同作品时按 Android 报“已导入”，不能悄悄搬走另一作品的卷。仅文件名相同不视为同内容。
- 新增原文件格式、指纹、归属与字节数元数据应为兼容旧 JSON 的可选字段。旧 ZIP/文件夹目录缺少原包/原路径时，不伪造指纹，不靠错误算法重识别或丢弃旧书。
- 复制时保留至少 256 MiB 可用空间，未知总大小也逐块检查；空间不足、取消或验证失败不发布。实际导入、下载、派生缓存占用分别统计，不能遗漏保存原包与展开图片造成的双份空间。

## 本地操作与恢复

- 重命名保存非空 Android trim 后的用户标题；只有落盘成功才更新详情和书架，失败保留输入。原文件和原始标题不修改。
- 新卷追加时目标作品必须仍存在且可写。异步准备完成后再次检查操作代次与目标；用户删除作品后，旧任务不能创建同名替代作品或把卷写回新身份。
- 卷重排必须是当前完整卷 ID 的排列，拒绝重复、缺项和外部卷。事务保留卷内原章节顺序、所有章 ID 及其他卷的位置记录。
- 删除单卷只影响本作品所拥有的精确物理卷。首卷被删后系列身份仍存在；最后卷删除等同整书删除。删除状态先持久化，文件清理失败保留可重试状态，不能先报成功。
- 整书删除保留收藏/历史和原文件，在同一目录快照中保留指纹、作品/卷身份、用户标题墓碑，以供同内容重新导入恢复。明确清除历史时才清对应恢复身份，不能自动“修复”成新历史。
- 清理必须校验精确路径和归属，不用 UUID 前缀模糊匹配，不跟随外部符号链接，不递归操作书库根。写入/回收要考虑操作期间的目录替换，复用 Task39 已证实的目录身份原则。

## 阅读路由

一个明确的阅读目标把系列 ID、稳定章 ID、当前全局章序号映射到物理卷、卷内章序号与正文资源。

- 图片/PDF 沿用漫画阅读器；文字/图文沿用电子书阅读器。跨卷下一章可能切换阅读器类型，目录选择亦然；不能停在 requiresTextReader 错误页，也不能为每次换章不断增加导航栈。
- 文字 session 内部可复用现有 EpubTextSession 的卷内导航；保存时将定位转换成系列历史身份，恢复时先按章 ID 找到新章序，再验证该物理卷内资源/spine。不能因为分卷重排而清空位置。
- WK 资源授权仍只绑定正在阅读的物理卷；系列拥有多个 EPUB 不等于单个页面可以跨卷读取任意资源。
- 原单卷阅读、旧 history/locator JSON、纯图片单卷及有重复 href 的 EPUB 均须回归。
- 删除当前章节后只对失效章选择可用回退，不删除整本或其他章的历史。已删除本地书的历史保留可辨识标题和“重新导入”提示，不能使历史列表整体失败。

## 批量流程和界面

- 元数据扫描、分组规划、持久批次状态、内容指纹采用 Tasks40–43 的接口。
- 多选后按书籍元数据/文件名给出建议分组与卷序；本地同名合并需要用户确认，远程文件按原作品身份分组。用户可选择分开导入或明确合并，不自动按同名改已有书。
- 输入文档的安全作用域授权必须覆盖扫描和复制；持久恢复需要系统书签或 App 已拥有副本。持久 JSON 中的 URL 字符串本身不是跨启动权限，不可拿它假装恢复成功。
- 已完成/已跳过项不重跑；失败项不阻塞后续项，可单独重试。取消后保留已完成书籍、回收未完成副本，迟到回调不能复活任务。重试前先确认旧 worker 已停止。
- 卷管理按 Android：72% 底部面板、拖动落手只保存一次、忙时禁用冲突操作、删除后 3.5 秒撤销，下一次删除/关闭/离开前提交待删项。不能在忙时丢失已承诺的待删除操作。
- 本地详情保留格式/实际大小/多卷数量、原素材、重命名/删除失败重试及明确“仅删除 App 副本”说明。下载书后续必须通过下载 runtime 统一清理队列与存储。

## 验证要求

按依赖顺序分任务实现：准备/指纹与旧接口兼容 → 目录快照/删除恢复 → 导入协调与去重 → 系列阅读路由 → 批次 worker/文件授权 → 批量与卷管理界面。每项用真实临时文件验证失败、取消、重开和竞争，不以 mock 格式支持或空页面代替。

Windows Docker 只验证核心与 Swift 语法；Apple 类型检查、Files/书签、APFS、混合卷阅读与手势、内存和完整视觉仍必须在 macOS/iPhone 验收。没有这些证据，不声称 1:1 复刻完成。
