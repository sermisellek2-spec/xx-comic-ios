# 当前阅读模式与旧按钮偏好兼容

固定 Android 2.0.40/340、`696e80a44ab36b19de6f630565df32978e55a19e`。父提交为 ed3e2bc；真实站源验收继续按用户指令暂停，目录/配置及确定性用户流程仍保留。

逐消费者检查发现：旧 `reader.page.mode=1` 或 `reader.button.mode=true` 会让 iOS 普通/日漫模式禁用点按和横滑。现有底栏“上一章/下一章”只切章，不能替代旧单页按钮。冻结安卓确实仍兼容旧输入值并有额外52dp按钮栏；当前设置已没有输入方式选择。按照用户只保留当前功能、避免难用交互的要求，iOS 的三个当前模式直接使用现行翻页规则，旧值保留在数据中，不重新增加淘汰的输入方式入口或按钮栏。

普通模式左右点按/横滑、日漫右向左、卷轴侧点不切章保持各自规则。多指、缩放、取消、距离/速度条件及旧左右手停用不变。新增 UI 用例通过真实偏好存储种入旧按钮状态，验证普通模式点按和滑动、切日漫后的反向交互，以及退出重启后的日漫页码和滑动。原93项 UI 全部保留，当前源码共94项；新增用例尚未在 Apple 运行。

当前93个原生 Swift 文件 Release/DEBUG 语法分别退出0；ComicCore的269个输入与上一轮完整Linux928项/2 Apple PDF跳过/0失败记录完全一致，没有改动核心和旧偏好断言。[当前输入与检查](verification.json)、[基线与消费者核对](entry-consumer-audit.json)。语法检查不代表原生构建或UI通过。

父输入 ed3 的完整 Apple 回归仍在运行，不能把它的后续结果当作本次兼容修正的运行证据。当前完整门槛和总验收IPA尚未完成。打包及开发CI仅使用 sermisellek2-spec/xx-comic-ios。
