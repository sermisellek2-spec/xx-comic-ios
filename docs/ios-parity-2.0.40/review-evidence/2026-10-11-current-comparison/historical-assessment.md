# iOS 与 Android 2.0.40 当前差异评估

核对日期：2026-10-11。范围仅为 Android 2.0.40 / versionCode 340 的冻结发布基线 `696e80a44ab36b19de6f630565df32978e55a19e`；不把更早版本曾经存在、当前版本已经移除的能力列入 iOS 目标。

## 结论

iOS 当前版本已经覆盖主要用户闭环：书架与分组、发现与全站搜索、详情与换源、目录、漫画/文字阅读、本地导入、下载、设置、更新提示、使用统计和离线 AI 2 倍超分都有实际 UIKit 入口或生产接线。它不是“功能只做了一半”的状态。

2026-10-11 补充：产品要求以当前功能集为准。阅读器的“左手翻页”已被确认是淘汰功能，即使冻结 Android 源码仍残留实现，也不得在 iOS 保留入口或行为；iOS 读取旧偏好时忽略 `reader.left.hand`。

2026-10-11 再补充：此前 IPA 安装后没有主屏图标的原因，是工程缺少 `AppIcon` Asset Catalog 和 `ASSETCATALOG_COMPILER_APPICON_NAME`。当前工作树已按 iPhone、iPad 和 App Store 共 18 个规格补齐图标，并复用 Android 当前启动图标作为来源；静态像素规格已校验，仍须以新 GitHub Actions 产出的 IPA 核验 `CFBundleIcons`、`Assets.car` 与真机主屏显示。

2026-10-11 复核补充：iOS 设置入口此前仍写有“切换阅读页左右触控区”，而实际已不提供左右手配置；该遗留文案已改为当前的“布局、翻页方式与图像增强”。版本更新元数据缺少下载链接时，回退地址也已改为当前 iOS 仓库的 Releases 页面，保证用户能在浏览器中寻找安装包。

但当前不能作为最终对齐版本交付。根本原因不是页面完全不能用，而是：

1. 没有 Android 与 iOS 在同一内容、同一逻辑宽度下的截图金标、叠图和逐组件差分。因此目前的 iOS 运行截图只能证明页面可运行，不能证明视觉复刻达到可接受水平。
2. 当前 iOS `HEAD` 为 `1e2287c`，最后一次已有原生运行验证停在 `7162e15`。`8bf6bfa` 的 Release 夹具修复、之后的 EPUB 修复及当前的 App Icon/淘汰左右手改动尚未获得新的原生 Release/IPA 验证。用户已确认新 GitHub Actions 仓库可以构建；远端仍停在 `a5aeec9`，必须推送当前提交并以其实际产物替代旧 IPA。
3. 首页、详情、设置、弹层仍有较多 UIKit 标准控件和 SF Symbols。它们本身不粗糙，但与 Android 的自定义标题、工具区、图标、抽屉和操作区相比，产品识别和信息密度存在可见差异，不能以“iOS 原生风格”结束复刻。

冻结基线已于本轮重新运行 `verify-baseline.ps1` 并通过：527 个文件与参考包 SHA-256 均匹配。

## 视觉和交互差异

本轮目视检查了 Android 现有运行截图及 iOS 的 iPhone/iPad 运行截图。两端内容夹具不同，以下是组件级判断，不是像素比较结论。

| 优先级 | 差异 | 现状与影响 | 处理标准 |
| --- | --- | --- | --- |
| P0 | 缺少同内容视觉金标 | `BASE-05`、`GATE-02`、`GATE-06`、`FINAL-01` 仍为待验收；不能从独立的 iOS 矩阵推导“视觉通过” | 以确定性本机 HTTP fixture 同时驱动两端；覆盖书架、发现、详情、阅读器/目录、下载、设置、错误/空态，按 iPhone/iPad、横竖屏、深浅色保存截图、叠图和逐组件问题单 |
| P0 | 已修复但未在 IPA 确认的应用图标 | 原工程未配置 App Icon，因此安装包可能没有主屏图标；现已加入完整 Asset Catalog 和编译设置 | 新 CI 成功后解包确认 `CFBundleIcons`/`Assets.car`，并在真机或模拟器主屏检查图标显示；在此之前不能关闭 `VIS-02` |
| P1 | 全局导航仍偏系统样式 | iOS 使用 `UITabBarController`、`UINavigationController` 和 `books.vertical` / `safari` / `gearshape`；Android 是应用自有标题、底栏图标和工具区 | 保留 iOS 安全区、返回手势和动态字体，但按 Android 的图标语义、标题字号、分隔线、底栏高度和选中态重绘应用内容区 |
| P1 | 书架头部与封面降级状态不一致 | 历史 iOS 书架截图中“书架/历史/导入”采用导航栏文字按钮，且缺封面条目显示为纯亮蓝矩形；Android 使用更强的书架标题、工具按钮和统一“没有封面”素材 | 无封面必须使用与 Android 相同的占位语义，不能出现无说明的纯色块；书架的分段、分组栏、接着看、导入和布局切换应按同内容截图调节密度 |
| P1 | 发现页控件形态不同 | iOS 的 `UISearchBar`、`UISegmentedControl` 与文本按钮可用且清晰，但 Android 的搜索/站源/筛选组合更像一个统一的自定义工具区 | 先对齐搜索框高度、边框、按钮优先级、分组入口、结果标题和网格间距；不必照搬 Android 系统状态栏 |
| P1 | 详情页仍是通用纵向表单感 | iOS 详情使用 `UIStackView`、文字按钮和固定 280pt 封面；Android 当前详情有更明确的作品信息层级和阅读操作区 | 按作品元数据的长标题、空描述、加载、失败、已收藏/未收藏、续读和换源等状态逐一调整，不以测试封面截图判断成品质量 |
| P1 | 设置页/系统弹窗的产品感不足 | 读取设置页可见大块 `UITableView` 卡片、系统 `UISegmentedControl`/`UISwitch`；不是低质量，但与 Android 自定义设置抽屉差异明显 | 需要统一设置分区、行高、标题、开关颜色和说明层级；系统文件选择器、分享和权限弹窗可以保留原生表现 |
| P1 | 当前页面仍保留明显 UIKit 默认控件 | 根导航使用 SF Symbols；设置和阅读设置直接采用 `UITableView`、`UISegmentedControl`、`UISwitch`，部分操作使用系统 Alert | 功能可用但尚未达到 Android 的统一产品层级；用同内容双端截图确定尺寸后，重绘应用导航、设置和业务弹层，系统权限/文件选择器保持原生 |
| P1 | 阅读器已接近目标但仍需交互对照 | iPad 截图显示底部控制条、进度拖动、目录/换源/设置和 AI 2X 状态已具备，完成度高于其他页面 | 用真实图片和同章节逐项检验：轻触/横滑不误切章、缩放/平移/取消不翻页、旋转后图内位置、原图对照、长图内存和目录快滚；不保留淘汰的左右手模式 |
| P2 | iPad 不能只放大 iPhone 布局 | 当前网格已按可用宽度动态列数，主要弹层已有 popover 保护 | 在同一 fixture 下逐页看横竖屏，保证标题、分组栏、详情动作、抽屉和下载队列不会留出无意义的大空区或发生截断 |

## 功能验收和平台边界

以下项目不应被当成“iOS 缺功能”，但需要保留明确的实现和验收标准。

| 项目 | 正确的 iOS 行为 | 当前判断 |
| --- | --- | --- |
| 应用更新 | 发现版本后解释更新内容并打开浏览器/分发渠道；不下载和安装 APK | 已实现，属于可接受的平台等效 |
| 文件授权 | 使用 `UIDocumentPicker`、安全作用域书签和失效后重新授权入口 | 已有实现；需真实设备验证跨启动恢复 |
| 后台下载 | 任务离开前台不能伪称永久运行；应可恢复、显示失败并重试 | 代码有恢复/重试闭环，仍需 Apple 生命周期实测 |
| 真实站源 | 在非站源门槛通过前只使用确定性 fixture，不以少量网页成功替代验收 | 当前仍按此顺序暂停真实站源验收 |

## 已剔除功能的处理规则

本轮静态排查未找到一个同时满足“Android 2.0.40 已移除、iOS 仍有可见入口、删除不影响当前数据/流程”的功能，因此没有直接删除产品代码。不能把下列内容误删为历史功能：

* `SourcePreferences.legacyAliases`、分组迁移等旧数据读取代码：用于升级后保留既有书架、站源开关和排序，不是用户可见的旧功能。
* `EpubUITestFixtures`：只在显式 `--ui-testing` 参数启用，Release 不会伪造图书或下载结果。
* EPUB/PDF/Kindle、本地文件夹同步、使用统计、站源分组、追更和浏览器更新：Android 2.0.40 仍包含对应流程，应继续保留。
* 左右手翻页和日漫模式：由产品当前要求明确淘汰，已从 iOS 设置、持久化和手势映射中移除；遗留 `reader.left.hand` 数据会被忽略。
* 应用图标：不是可删除的历史功能。已补齐 Xcode Asset Catalog，必须随最终 IPA 一起验收。

后续每个删除候选必须同时满足以下条件才可删除：Android 冻结源码不存在当前入口；iOS 不从任何当前页面、恢复任务或持久化迁移调用；删除后有针对导入、历史、收藏、下载和设置恢复的回归证据。历史报告、旧 baseline JSON 和测试材料可标记为过时，但不应伪造为当前交付依据。
