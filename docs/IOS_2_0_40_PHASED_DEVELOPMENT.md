## 阶段验收与证据规则

每阶段分开记录核心、Apple构建、UI运行、视觉、性能/恢复。阶段报告放 `docs/ios-parity-2.0.40/stages/`，需求状态继续使用待核对/待实现/待验收/通过/失败/阻塞/后置站源。检查失败先定位修复，跑影响回归后做本阶段完整验收；必需未跑项不得标通过。

正常、空、加载、失败、重试、取消、重启/恢复及浅深色/尺寸状态是每阶段必测闭环。截图记录提交、设备/逻辑尺寸/像素尺寸、字体比例、fixture、步骤和SHA-256；系统区遮罩事先声明，不遮应用缺失。颜色、间距、对齐、图标、文案、截断和反馈逐组件检查，不能只给全图相似率。

Linux Swift测试或语法检查不能替代Apple类型检查、UIKit、图像/PDF、WebKit、Files与iPad。早期使用指定仓库取得当前原生结果，失败日志也保存；未通过时不打最终验收包。不能删除失败测试、降低断言、用旧截图/IPA替代当前结果。

阶段失败由代理修复，不向用户追加选择题。确实涉及账号验证码、不可获得的外部环境、新增费用或破坏性范围冲突时，将已尝试路径、具体缺项、影响与最低必要动作写入 `USER_ITEMS.md`，继续其他不依赖该项的工作，最后一次集中汇总。若不可绕过的缺项阻止完整交付，最后明确哪些未完成，不能邀请用户“先试试”来代替自验。
